# 人員主資料與授權基礎服務

護理部是主資料的維護者。各數位平台持有自己的業務資料，使用固定人員 ID 關聯本中心，不以姓名配對。固定 ID 在轉調、留停及復職時沿用；原始到職日保留。

## 資料結構

| 資料表 | 用途 |
| --- | --- |
| units | 護理單位與代碼 |
| staff | 員編（唯一）、姓名、目前單位、職務、能力分級、原始到職日、狀態、版本 |
| events | 修改前後快照、生效日、實際登錄時間、操作身分；不提供一般刪除功能 |
| platforms | 護理部登錄的數位平台 |
| grants | 每人／每平台的明確使用資格 |
| clients | 各串接呼叫端、金鑰雜湊、可讀單位、平台資格篩選、撤銷與最近呼叫時間 |
| meta | Demo 初始化版本 |

種子建檔使用伺服器端交易；資料儲存在 D1，跨瀏覽器共用。瀏覽器不保存人員主檔。管理畫面由 Sites 登入身分加上 NURSEHUB_ADMIN_EMAILS 名單授權；公開分享使用原始碼內固定虛擬快照，不讀取管理資料庫。一般登入訪客也只能瀏覽虛擬快照。正式單位主管的細緻分權仍待院內定義。

## 各平台如何接入

1. 護理部在「數位平台」新增平台，為人員勾選資格。
2. 在「API 串接」建立呼叫端。選擇可讀取單位，以及是否只讀取有該平台資格的人員。
3. 完整金鑰只顯示一次，放到串接平台後端的秘密設定，不放在網址、公開前端或 Git。
4. 網站目前開放公開唯讀分享，服務 API 仍須使用本中心的專用金鑰。若未來改回私人 Sites，機器呼叫另外需要 Sites 入口授權；不要把分享頁的固定虛擬資料當成正式主資料來源。
5. 先記錄 changes 游標，再拉取完整 staff 清冊，接著接續拉取游標後的新異動，以處理第一次同步期間的變動。來源 staff 清冊是目前資格的權威值。
6. 每頁最多掃描 100 個異動，持續讀取到 `hasMore=false`。即使 `data` 為空，也要保存回傳的 `cursor`。平台資格或單位授權範圍變更時，重新做完整同步。
7. 以 `id` 做 upsert，以 `version` 協助去重。`eligible=false` 須立即移除或停用外部平台的本地資格；`true` 則重新查詢清冊。平台須定義自己可接受的同步延遲；本版未提供 webhook 或背景排程。

```http
GET /api/v1/staff?unitId=U01&limit=100&offset=0
X-API-Key: <本中心平台金鑰>
```

此示例全部為佔位文字。公開版不需額外 Sites 入口標頭。

| 介面 | 功能 |
| --- | --- |
| GET /api/v1/staff | 只回傳在職且符合金鑰單位及平台資格的人員；支援 unitId、q、limit、offset |
| GET /api/v1/units | 只回傳金鑰授權單位 |
| GET /api/v1/changes?after=0 | 依登錄順序的游標同步；回傳 seq、staffId、type、effectiveDate、recordedAt、eligible |
| GET /api/openapi | 公開 OpenAPI JSON |

staff 回傳 `{data,total,limit,offset,apiVersion,generatedAt}`。changes 回傳 `{data,cursor,hasMore,apiVersion}`。changes 只提供最少異動資訊，不回傳完整前後快照；轉出授權單位的人員仍會通知原呼叫端，以利停用。

## 人員異動規則

- 異動立即登錄目前狀態；生效日期不可晚於今天，不支援預排未來異動。輸入日期依臺灣時間判定。
- 可補登過去異動，但日期不得早於原始到職日或最近一筆人員狀態／單位異動。這版未實作回溯某日的完整清冊查詢。
- 轉調保留人員與歷史及明確平台資格。受單位範圍限制的呼叫端，會依新單位重新篩選；平台也須配合異動同步。
- 離職與留停會把全部 grants 停用；復職沿用 ID，須重新授權。這是 Demo 的明確產品規則，可依正式管理辦法調整。
- 職務與平台資格分開管理。修改職務不會自動新增主管平台資格；需要管理員明確指定。
- 修改使用版本比較與資料庫交易。版本過期回傳 409，不覆蓋其他人的操作；事件與人員更新一起成功或失敗。
- 服務 API 唯讀；金鑰可獨立撤銷，資料庫只存雜湊。管理操作由登入後專用 API 執行。

## 正式基礎設施的下一階段

已實作的是可運作的基礎服務首版。正式院內上線還需：實際管理員／單位主管權限、備份與復原演練、監測及流量限制、憑證輪替流程、各平台停權延遲驗收、部署及維運責任分工。此 Demo 沒有串接真實人事、SSO、教育平台或建立院內正式帳號。

公開清冊、共用密碼、國民身分證與個人聯絡方式不在資料模型內。正式欄位與保留規範由護理部及院內負責單位確認。
